# 海外 App 投放个人 BI 看板设计

## 1. 项目目标

构建一个桌面优先的个人 BI 看板，用于汇总和分析海外 App 推广广告数据。首版先完成高保真 UI 和本地可运行网页，使用模拟数据验证信息架构、指标口径和交互体验。后续再部署到云端，并接入广告平台及归因平台的实时数据。

看板需要同时支持三类工作：

- 日常总览：快速掌握花费、安装、激活、付费、ROAS 和 LTV。
- 投放优化：定位平台、国家、广告系列、广告组及素材层级的异常。
- 管理汇报：展示预算进度、趋势、目标完成度和跨平台表现。

## 2. 首版范围

### 2.1 广告平台

首版模拟以下六个平台的数据：

- Meta Ads
- Google Ads
- TikTok Ads
- Microsoft Ads
- LinkedIn Ads
- X Ads

### 2.2 业务类型

项目聚焦 App 推广，统一呈现完整投放漏斗：

`Impressions -> Clicks -> Installs -> Activations -> Payers -> ROAS / LTV`

### 2.3 分析维度

支持以下维度及逐层下钻：

`App -> Platform -> Account -> Country -> OS -> Campaign -> Ad Group -> Creative`

所有金额统一换算并显示为 USD。首版不展示广告账户原始币种。

### 2.4 数据范围

首版仅使用本地模拟数据，不接入真实 API。模拟数据需要覆盖多个 App、账户、国家、OS、广告系列、广告组和素材，并包含正常、异常、空数据及延迟数据场景。

## 3. 技术架构

### 3.1 前端技术

- React
- Vite
- TypeScript
- ECharts

首版是纯前端本地应用，不需要后端服务。开发模式通过 Vite 本地服务器运行，生产构建生成标准静态网页资源。

### 3.2 应用结构

应用由三个主要页面组成：

1. 首页管理大屏
2. 投放分析
3. 素材分析

页面共享统一的筛选状态、指标模型、数据适配层和基础 UI 组件。

### 3.3 数据适配层

使用统一的 `DataProvider` 接口隔离页面与数据来源。页面只依赖标准化后的业务模型，不直接依赖具体广告平台字段。

首版实现 `MockDataProvider`，从本地模拟数据读取记录。后续接入 AppsFlyer、Adjust、广告平台 API 或云端数据仓库时，通过新增适配器完成映射，不改变页面组件和指标计算接口。

标准模型至少包含：

- 日期和更新时间
- App、平台、账户、国家、OS
- Campaign、Ad Group、Creative
- Impressions、Clicks、Installs、Activations、Payers
- Spend、Revenue、Budget
- CTR、CVR、CPI、CPA、Activation Rate、ROAS、LTV

派生指标由统一指标模块计算，避免各页面重复实现或产生口径差异。

## 4. 信息架构

### 4.1 全局框架

应用采用桌面管理大屏布局：

- 顶部区域放置页面标题、全局筛选和数据更新时间。
- 主导航提供首页、投放分析、素材分析入口。
- 页面内容使用紧凑栅格，不使用营销落地页式大标题或装饰性卡片。
- 明细分析通过独立页面承载，避免首页信息过载。

### 4.2 全局筛选

所有页面共享以下筛选条件：

- 日期范围
- App
- Platform
- Account
- Country
- OS

筛选变化后，当前页面的 KPI、图表、异常和表格同步更新。页面提供一键重置，并明确展示无匹配结果状态。

## 5. 首页管理大屏

首页强调管理汇报和跨平台总览。

### 5.1 顶部信息

- 页面标题
- 当前日期范围
- 全局筛选控件
- 数据最后更新时间
- 当前金额口径 USD

### 5.2 核心 KPI

首屏展示：

- Spend
- Installs
- CPI
- Activation Rate
- Payers
- D7 ROAS
- D30 LTV

每个指标显示当前值、对比周期变化和状态颜色。变化值需要区分“数值上升”和“业务表现变好”，例如 CPI 上升应显示为负向状态。

### 5.3 趋势与预算

- Spend 与 Installs 双指标趋势
- ROAS 趋势
- 预算消耗进度
- 目标周期进度与预算节奏对比

### 5.4 平台与地域

- 六个平台横向表现对比
- 国家表现排行
- 地域分布图
- 平台或国家选择可联动页面筛选

### 5.5 异常提醒

首版使用前端阈值规则检测：

- CPI 较上一等长周期上涨 20% 或以上
- D7 ROAS 较上一等长周期下降 15% 或以上
- 预算消耗进度高于时间进度 10 个百分点或以上
- 数据更新时间距当前时间超过 24 小时

异常项包含严重程度、影响范围、当前值、对比值和进入分析页的操作。
所有阈值集中定义在异常规则配置模块中，首版界面不提供用户自定义入口。

### 5.6 汇总明细

首页底部提供平台或 Campaign 汇总表，支持排序。点击行后携带当前筛选条件进入投放分析页。

## 6. 投放分析

投放分析页面用于逐层定位表现问题。

主要内容包括：

- 当前下钻路径面包屑
- 可切换的分析维度
- 漏斗图
- 指标趋势
- 排名与贡献度图表
- 可排序、搜索的明细表

用户可以从 Platform 逐层进入 Account、Country、OS、Campaign、Ad Group 和 Creative。点击图表或表格行时，其他模块联动更新。面包屑用于返回任意上级层级。

## 7. 素材分析

素材分析页面聚焦 Creative 层级表现。

每条素材记录包含：

- 模拟缩略图
- 素材名称和类型
- Platform、Campaign、Ad Group
- Spend、CTR、CPI、Activation Rate、ROAS
- 表现状态

页面支持按平台、素材类型和表现状态筛选，并支持搜索、排序和查看素材指标趋势。首版缩略图和数据均为本地模拟内容，不连接真实广告资产。

## 8. 视觉与语言

### 8.1 视觉方向

采用“数据报告感”：

- 低饱和分区色
- 细边框与清晰表格线
- 紧凑但有呼吸感的排版
- 重点指标使用有限的绿色、红色和辅助色
- 避免传统深蓝科技大屏、渐变光效和纯装饰元素

页面以浅色背景为主，强调高质量商业报告的秩序感和辨识度。

### 8.2 界面语言

采用中文操作界面并保留英文广告指标名，例如：

- 总花费 Spend
- 安装量 Installs
- 单次安装成本 CPI
- 激活率 Activation Rate
- 付费用户 Payers

## 9. 响应式设计

### 9.1 桌面

桌面是主要使用场景，完整展示 KPI、趋势、预算、平台、地域、异常和明细。

### 9.2 平板

平板保留全部功能，栅格调整为较少列数，筛选控件可折叠。

### 9.3 手机

手机端提供精简视图：

- 核心 KPI
- 主要趋势
- 异常提醒
- 平台排行

复杂表格使用横向滚动，不强行压缩列宽。素材列表切换为纵向条目。

## 10. 状态与错误处理

所有主要模块需要覆盖：

- 初始加载
- 加载失败
- 空数据
- 筛选无结果
- 数据延迟
- 部分平台数据缺失

错误状态需要说明影响范围，不应使整个页面因单一模块失败而不可用。

## 11. 测试与验收

### 11.1 自动化测试

重点覆盖：

- 指标和派生指标计算
- USD 金额汇总
- 全局筛选联动
- 下钻路径与面包屑
- 异常规则
- `DataProvider` 数据映射
- 空数据和错误状态

### 11.2 浏览器验证

在桌面、平板和手机视口检查：

- 图表正常渲染且非空
- 文字、图例和控件不重叠
- KPI 数值不会撑破容器
- 表格和筛选可用
- 页面跳转及筛选状态传递正确

## 12. 分阶段交付

### 阶段一：UI 与本地网页

- 完成设计系统和页面组件
- 完成三个页面
- 接入模拟数据
- 实现筛选、下钻、排序和异常展示
- 本地运行并完成响应式验证

### 阶段二：云端部署

- 选择静态托管平台
- 配置生产构建和环境变量
- 建立预览与正式发布流程

### 阶段三：实时数据

- 确定广告平台及归因平台的数据获取方式
- 实现服务端数据采集和存储
- 新增真实 `DataProvider`
- 配置定时或实时刷新、缓存和数据质量监控

## 13. 非首版范围

以下内容不进入首版本地 UI：

- 真实广告平台授权
- AppsFlyer 或 Adjust 接入
- 用户账户和权限系统
- 云端数据库
- 自动调价或广告操作
- 自定义报表编辑器
- 导出 PDF 或定时邮件
