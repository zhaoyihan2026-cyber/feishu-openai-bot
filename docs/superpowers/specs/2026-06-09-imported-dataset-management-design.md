# 投放 BI 导入与本地数据管理设计

## 1. 项目目标

在现有海外 App 投放 BI 的基础上，新增一个可平台化迁移的数据管理能力。第一版不接后端，先支持用户在浏览器里导入 CSV 和 Excel `.xlsx` 文件，自动识别常见广告数据字段，校验并标准化为现有 `AcquisitionRecord` 模型，然后保存为本地数据集版本。BI 页面启动时优先读取当前生效的导入版本；没有导入数据时继续使用现有模拟数据。

该能力要解决三个问题：

- 真实平台导出的表格可以直接跑进 BI。
- 导入过程可检查、可回滚、可重复使用。
- 后续接后端或广告平台 API 时，页面和指标计算不需要重写。

## 2. 首版范围

### 2.1 文件格式

首版支持：

- CSV
- Excel `.xlsx`

不支持 `.xls`、压缩包、多文件合并上传、在线表格链接或直接广告平台 API。`.xls` 可以在后续通过用户另存为 `.xlsx` 或服务端转换来支持。

### 2.2 字段识别方式

首版使用自动字段识别，不做手动字段映射向导。系统维护一份字段别名表，把常见字段名映射到标准字段。例如：

- `spend`、`cost`、`消耗`、`花费` -> `spendUsd`
- `campaign`、`campaign name`、`广告系列` -> `campaign`
- `installs`、`安装`、`首次安装` -> `installs`

字段匹配时统一做大小写、空格、下划线、连字符和常见中英文标点归一化。后续遇到新平台字段名时，只扩展别名表，不修改页面代码。

### 2.3 数据保存方式

导入结果保存在浏览器本地。优先使用 IndexedDB 存储数据集、版本和记录；如果当前浏览器不支持 IndexedDB，则显示不可用状态，不自动降级到容量较小的 localStorage。localStorage 只可用于保存很小的 UI 偏好，不保存导入记录。

## 3. 用户体验

### 3.1 导航入口

在现有主导航中新增“数据管理”页面，与“总览”“投放分析”“素材分析”并列。页面不承担 BI 图表分析，只负责导入、版本管理和数据源状态。

### 3.2 当前数据状态

数据管理页顶部展示当前生效数据源：

- 数据源类型：模拟数据或导入数据
- 当前版本名称
- 记录数
- 日期范围
- 平台数量
- 最后导入时间
- 数据质量摘要：有效行、错误行、警告数

如果当前使用模拟数据，页面显示“当前使用模拟数据”，并提示上传文件创建真实数据版本。

### 3.3 导入向导

导入流程分为四步：

1. 上传文件。
2. 解析文件并展示字段识别结果。
3. 展示前 20 行标准化预览、错误摘要和警告摘要。
4. 用户确认导入方式并保存为新版本。

导入方式包括：

- 覆盖：基于本次有效行创建一个全新版本。
- 追加：把本次有效行追加到当前生效版本后创建新版本。

追加导入不会直接修改旧版本。所有确认导入都会创建新版本。

### 3.4 版本列表

版本列表展示所有本地数据版本：

- 版本名称
- 创建时间
- 导入方式：覆盖或追加
- 记录数
- 日期范围
- 平台列表
- 有效行、错误行、警告数
- 是否当前生效

用户可以：

- 设置某个版本为当前生效版本。
- 回滚到旧版本。
- 删除非当前版本。
- 清空全部导入数据，恢复使用模拟数据。

删除当前生效版本前需要先切换到其他版本，或清空全部导入数据。

## 4. 标准数据模型

导入后的记录必须标准化为现有 `AcquisitionRecord`：

- `id`
- `date`
- `updatedAt`
- `app`
- `platform`
- `account`
- `country`
- `os`
- `campaign`
- `adGroup`
- `creative`
- `creativeType`
- `thumbnail`
- `impressions`
- `clicks`
- `installs`
- `activations`
- `payers`
- `spendUsd`
- `revenueD7Usd`
- `revenueD30Usd`
- `budgetUsd`

导入模块只负责解析、映射、校验和补默认值。CTR、CPI、ROAS、LTV 等派生指标仍由现有指标模块统一计算。

## 5. 校验规则

### 5.1 必填字段

保存版本前，每一条有效记录必须包含：

- `date`
- `platform`
- `campaign`
- `spendUsd`
- `impressions`
- `clicks`
- `installs`

缺少以上字段的行进入错误行，不进入版本。

### 5.2 可选字段默认值

可选字段缺失时按以下规则补齐：

- `updatedAt`：使用导入确认时刻。
- `app`：`Unknown App`
- `account`：`Unknown Account`
- `country`：`Unknown`
- `os`：`iOS` 和 `Android` 之外的值统一为 `iOS`，并生成警告。
- `adGroup`：`Unspecified Ad Group`
- `creative`：`Unspecified Creative`
- `creativeType`：无法识别时使用 `Image`，并生成警告。
- `thumbnail`：空字符串。
- `activations`：`0`
- `payers`：`0`
- `revenueD7Usd`：`0`
- `revenueD30Usd`：`0`
- `budgetUsd`：`spendUsd`

### 5.3 平台归一化

平台字段支持常见别名：

- `meta`、`facebook`、`fb` -> `Meta Ads`
- `google`、`google ads`、`adwords` -> `Google Ads`
- `tiktok`、`tt` -> `TikTok Ads`
- `microsoft`、`bing`、`bing ads` -> `Microsoft Ads`
- `linkedin` -> `LinkedIn Ads`
- `x`、`twitter` -> `X Ads`

无法识别的平台进入错误行，不进入版本。首版仍沿用现有六个平台枚举，不新增自由平台名。

### 5.4 日期和数字

日期支持：

- `YYYY-MM-DD`
- `YYYY/MM/DD`
- Excel 日期序列

数字支持：

- 普通数字
- 带千分位逗号的数字
- 带 `$` 的金额
- 空字符串

必填数字字段为空或无法解析时进入错误行。可选数字字段为空时使用默认值。负数在花费、展示、点击、安装等字段中视为错误。

## 6. 架构设计

### 6.1 数据入口

继续保持 `DataProvider` 作为页面唯一数据入口。页面只读取标准化后的 `AcquisitionRecord[]`，不感知文件格式、本地存储或版本管理。

新增：

- `ImportedDatasetRepository`：保存数据集、版本、当前生效版本和导入摘要。
- `ImportedDataProvider`：从当前生效版本读取 `AcquisitionRecord[]`。
- `CompositeDataProvider`：优先使用导入数据；无当前生效版本时使用 `MockDataProvider`。

以后接后端时，替换 `ImportedDatasetRepository` 的实现即可。

### 6.2 导入流水线

导入流程由以下模块组成：

- `ImportParser`：读取 CSV/XLSX，输出原始行对象。
- `FieldMapper`：根据别名表识别标准字段。
- `RecordValidator`：转换类型、补默认值、生成错误和警告。
- `DatasetVersionBuilder`：根据覆盖或追加策略生成新版本。
- `DatasetSummary`：计算记录数、日期范围、平台列表和质量摘要。

每个模块都应可单独测试，避免把解析、校验和 UI 状态写在同一个组件里。

### 6.3 本地存储

IndexedDB 中保存：

- 数据集元数据
- 版本元数据
- 当前生效版本 id
- 每个版本的标准化记录
- 每次导入的错误和警告摘要

错误行的原始数据只保存必要摘要，不长期保存完整原始文件内容，避免本地存储膨胀。

## 7. 错误处理

导入失败分为四类：

- 文件读取失败：提示重新上传。
- 格式不支持：提示只支持 CSV 和 `.xlsx`。
- 字段识别失败：提示缺少必填字段，并列出未识别列名。
- 行级校验失败：有效行可以继续导入，错误行不进入版本。

如果一个文件没有任何有效行，不能保存版本。

## 8. 测试要求

首版需要覆盖：

- CSV 解析。
- `.xlsx` 解析。
- 字段别名映射。
- 平台归一化。
- 日期解析。
- 数字解析。
- 必填字段缺失。
- 可选字段默认值。
- 覆盖导入创建新版本。
- 追加导入创建新版本且不修改旧版本。
- 当前生效版本切换。
- 无导入数据时回退到 mock 数据。
- 数据管理页的主要状态和按钮行为。

测试优先覆盖纯函数和仓库行为，再补 UI 交互测试。

## 9. 非目标

首版不做：

- 后端上传。
- 广告平台 API 授权。
- 多用户协作。
- 权限管理。
- 云端版本同步。
- 手动字段映射向导。
- 自定义平台枚举。
- 大文件分片导入。

这些能力可以在本地导入流程稳定后逐步加入。

## 10. 成功标准

完成后，用户可以在本地 BI 中上传 CSV 或 `.xlsx`，系统自动识别字段并生成可预览的标准记录。确认导入后，数据管理页出现新版本，BI 总览、投放分析和素材分析使用该版本数据。用户可以追加导入生成新版本，可以回滚到旧版本，也可以清空导入数据恢复模拟数据。
